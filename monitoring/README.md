# Monitoring

Prometheus collects metrics of the VM, the containers and the consumers and computes the estimated cost. Grafana shows both on one dashboard. Everything starts with the rest of the stack.

| Service | Port | |
|---|---|---|
| `prometheus` | 3008 | Stores the metrics and computes the cost (`prometheus/rules/cost.yml`). The course Prometheus reads the VM's CPU and memory from it. |
| `grafana` | 3010 | Public dashboard, generated by `grafana/dashboard.py` |
| `node-exporter` | 9100, host network | VM CPU, memory, network and disk |
| `cadvisor` | internal | CPU per container |

Prometheus also scrapes the 16 consumers on port 8000: Kafka lag, processing time, notifications and skipped messages.

## Cost

The VM is a t3a.medium in eu-west-1 with a 20 GiB disk. Idle it costs about $0.049/h, or $35/month.

| Part | Price | Grows with load |
|---|---|---|
| instance | $0.0408/h | no |
| public IPv4 | $0.005/h | no |
| disk (gp3) | $0.088 per GiB-month | no |
| CPU credits | $0.05 per vCPU-hour above 20% per vCPU | yes |
| outbound traffic | $0.09 per GiB | yes |

The CPU credits part ignores credits the VM has saved, so it is the worst case. The prices are at the top of `cost.yml`.

## Dashboard

- Estimated cost: projected cost per month, cost per part over time.
- Load: CPU per container against the VM's 2 vCPUs, with the 16 consumers added up, and the Kafka consumer lag.

Notification latency per message is in the consumer logs. `scripts/aggregate_consumer_sla.sh` adds up the summaries of the 16 consumers.

## Notes

- cAdvisor needs v0.57 or newer, because Docker 29 stores images in containerd.
- node-exporter uses the host network and PID namespace, so it measures the VM and not its container. Port 9100 is closed in the security group.
- The monitoring uses about 0.01 vCPU and 200 MiB of memory. Prometheus keeps 30 days or 1 GB.
- The API has no metrics of its own. A request histogram cost the Python API 11% throughput.
